# Changelog

All notable changes to FourEyes are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Because the kit is installed by copying files into a project's `.claude/`, "version" means *the kit source you copied from* — `/update-kit` reconciles a newer version against the manifest written at install time.

## [Unreleased]

### Added

- **Every executing skill writes its log back to the plan or card it was handed, not only to chat.** New `skills/implement/reference/work-log.md` generalises `/implement`'s Implementation Log into one contract that `/diagnose`, `/test`, `/test-spec`, `/refactor`, `/tdd`, `/perf`, `/clean-mvp` and `/sweep` now follow whenever `$ARGUMENTS` or a session brief names a planning artifact. The contract has five parts. (1) A ledger lives on disk from the first phase. (2) Each deviation is recorded with `Decided by` at the moment it is decided. (3) A dated `## <Skill> Log` section is appended, never overwritten, with Result · Changes made · Deviations · Verification · **Re-check later** · Findings not fixed here · Out-of-scope edits. (4) Status goes in the frontmatter, or in the log heading when the file has none. (5) The artifact is added to the commit suggestion. `Re-check later` is the section built for what gets lost: every check the session could not observe itself (a post-deploy log grep, a 24-hour count, a query after N events, a UI gesture) gets its command, a dated baseline captured now, and a pass condition. A bare description still gets the old suggest-only behaviour. The failure it fixes was measured on one project: in one parallel wave, six `/diagnose` sessions each fixed a card and left zero on-disk logs, so the close-out had only commit subjects to verify against, and the post-deploy checks those sessions could not run survived only in their transcripts. `rules/_generic/planning-artifacts.md` names the contract.

- **`/close-epic` now checks docs drift in the direction that actually rots: what the epic *added*.** A reference checker only verifies that mentioned things exist, so a module, command, dependency or invariant mentioned **nowhere** is invisible to it and scores as a clean pass — and in this kit the thing left stale is `.claude/PROJECT.md`, which every other skill reads first, so the cost is mis-routed future sessions rather than a wrong sentence. Phase 4b derives the delta from the epic's own commits, greps each new public name against the profile, the rules and the docs, and maps the finding to the artifact that owns it (Architecture, Canonical exemplars + wiring proof, Commands, Stack / Integrations, Deploy mapping, the glossary). One-line syncs land under the inline allowlist; **authoring a rule does not** — a rule is a claim about the whole repo argued from occurrences across it, and the close-out has read one epic, so it becomes a card routed to `/distill`, `/retro` or `/bootstrap`. The negative result is a reported row: "N surfaces checked, all present" is evidence, silence is indistinguishable from a skipped step. Measured on one project with the CLI-verb variant of the check: 2 of 38 registered commands had zero mentions across its rules, docs and root instructions.

- **`/close-epic` takes a batch, and leaves a board instead of chat text.** One invocation now accepts several epics: a *wave-batch* (one RUN-ORDER cutting across directories) still prices as one unit, while a *close-batch* of independent epics is tiered, verified, ledger-rowed and archived per epic under one run-level agent budget (≤8 live / ~12 spawned, one completeness critic for the whole set, mandatory `TaskOutput` collection). Two failures it closes: an unreadable plan status is now a straggler rather than a silent pass, and an epic named in the invocation but missing from the summary table is a reported non-close. Small documentation debt — dead refs, comments the epic's own diff falsified, typos in its plans — is fixed inline under a ≤15-line allowlist that explicitly excludes source behaviour, because a one-line bug fix at close is unreviewed, unowned, and buried in an archive commit. What survives the worth-it gate is **written to disk as a runnable epic** — `<topic>-followups/` with a board, one card per item, and session prompts — never proposed as chat text. Every card names its route (`/implement` · `/prepare` · `/diagnose` · `/analyst` · `/spike`) **and its `rec: <model>/<effort>`**, the same value in three places (card header, board `Rec` column, session heading), scored on `/prepare`'s shared complexity table plus its risk overlay rather than invented per file, with two close-out-specific calls the shared rubric does not make: a drive/measurement card is priced on how easy it is to fool yourself rather than on diff size, and a record-correction card is only mechanical until it re-points a grep other files pin. The prompt format is `/prepare`'s per-session brief rather than a lighter one of the board's own: the `## Execution Order` map is how parallelism gets stated (`W1: [01 ∥ 02] → W2: [03]`), `Solo: YES` carries its reason, `DO NOT TOUCH` is annotated `[NN · concurrent|future|merged]`, and the slash command stays the first line inside the fence — so two cards packed into one session get two blocks pasted as two messages, never one block with two commands, of which only the first would expand. Sessions are packed to the context budget. Measured on one project's history: 10 of 14 close-out sessions were immediately followed by the operator asking for exactly that artifact by hand. New `skills/close-epic/reference/followups.md` carries the tier; `Write` joins the skill's `allowed-tools`.

- **The worth-it gate defaults to *not* filing a card, and a board must clear a debt-stock check before it may exist.** Every finding gets exactly one of four dispositions — card · gated card · a named `known-undone` clause in the ledger row · dropped-with-evidence, with `finding-verifier` on anything the session did not observe itself — and the default is the `known-undone` clause. A row leaves it only by carrying a consequence sentence — `<class> · <who bears it> · <what goes wrong and by when>` — with the class from a closed list (data/money loss · a wrong number on a production path · user-visible breakage · shipped code with an unobserved verification · a blocked successor), and an explicit never-card list covers doc drift, stale tallies, tooling-vocabulary gaps, dev-tool test debt and rule polish argued from one epic. That sentence is a mechanical stand-in for a skeptic, because the session applying the gate is the session that authored the findings — `finding-verifier` rules on truth and never on worth, which is exactly the hole an operator post-mortem named: *"the worth-it gate failed because the author of the findings applied it to their own findings."* The failure mode it is priced against: a criterion a card can always meet — "something breaks **or misleads** if it is never done", and a stale comment misleads by definition — makes a card the cheapest outcome to argue for, and a close-out then spawns boards of its own size. Measured on one project, a chain **four generations deep** (feature epic → follow-ups → a successor epic → a residuals board), **8 open boards / 30 cards / 21 never started** at the moment a ninth was being authored, with five boards untouched for 46 / 15 / 14 / 5 / 5 days. So supply is gated on stock: ≥3 open follow-up boards, any board untouched >14 days, or an epic that is itself generation ≥2 → the run authors **no new board**, and survivors append to an open board, get parked with a trigger, or land in the ledger row; the stock line is reported with denominators whether or not a card is filed. Capping containers would not have caught that — 3 boards × 8 cards is twenty-four sessions. And **one approval line goes out before any file is written** — `NN <slug> · <class> · <route> · <rec>`, one line per card; the board is still authored on disk once the user says go, so this confirms *contents*, it is not a return to proposing boards as chat text. Filing zero cards and naming six known-undone clauses is a correct run, and the completeness critic's gaps are priced by the gate rather than each demanding a disposition above `known-undone` — the critic hunts absences and cannot price them, and most price at zero.

- **A path-keyed small-debt register, so the rows nobody cards land where a session will actually meet them.** A ledger clause is a verdict-index entry nobody opens looking for work, so a row whose fix fits a **ride-along** — ≲10 lines, written down in full — goes instead to a register keyed by path: new `skills/close-epic/assets/small-debt-register.md` ships the contract as an installable template, its location is a `PROJECT.md` field that `/bootstrap` asks for, the file itself is created on first use, and `rules/_generic/code.md` tells a session about to edit a file to grep the register and take its rows in the same diff. Anything too big for a ride-along stays a named known-undone clause, which is the honest artifact for real work nobody is scheduling. The register's contract is deliberately hostile to becoming a queue: rows are verified before filing, the fix is written out so nobody re-derives it, a row unclaimed for 90 days is deleted with its reason, and **no row count triggers anything** — a sweep fires on the operator's word only, boxed to docs/comments/anchors with every row re-verified first, because rows rot and a sweep that fixes without re-reading writes new drift over old. Measured on one project: an audit residue treated as a queue became a nine-plan epic, the rows having been cheap only while their files were already open.

- **Decision provenance on the review path.** A `/implement` deviation row now carries a fourth field, `Decided by`: `[AGENT]` unless the user's own words are pasted **verbatim**, in the language they wrote them, at the moment they answer — paraphrase, translation, and "the user approved this" are `[AGENT]`. The quote travels into the plan's `## Implementation Log` and into both Deviation Report tables, and `/code-review` Phase 1 opens by listing the decisions the diff embodies, reading the tag off that artifact cell rather than off memory: no quote, no `[USER]`. A review runs on the diff in a fresh session where the build conversation no longer exists, so the cell is the only evidence a decision was ever the user's — an agent that "remembers" one is precisely what the tag exists to catch.

- **Scenarios and numbers on acceptance criteria.** An AC that touches state, money, authorization, or an external contract now carries a named `GIVEN/WHEN/THEN` scenario (`/analyst` Phase 6 and `skills/analyst/assets/spec-template.md`), with the header naming the case and never its number; elsewhere it stays prose. ACs are quantified wherever the thing is measurable — "fast", "reliable", "handles large inputs" are not criteria until they carry a number and a unit — and `/grill` hunts those words as a lens rather than a checklist. One rule is one observable behavior: a line that needs an "and also" to finish is two rules. Left vague, the number is decided silently by whoever writes the code.

- **A verification-gap lens, and a stricter definition of "tested".** `/code-review` Phase 2 asks one added question: if the behavior the change was made for broke *where it is actually used*, would verification fail? `rules/_generic/testing.md` names the common way it would not — a test that exists but never ran (unregistered, filtered out, skipped, disabled) counts as missing, not as coverage, because a green suite that never executed the case reads exactly like a passing one.

- **A cap on the fix-and-re-audit loop.** `/implement`'s architecture audit stops after 3 rounds. "Re-audit until every modified file passes" has no stopping condition when auditor and implementer simply disagree; at the cap every open finding gets a named row, the plan goes to IN-PROGRESS, and the user decides. Continuing the *same* auditor rather than spawning a fresh one is unchanged.

- **A micro-test protocol for behavioral wording** (`skills/writing-skills`, with the heuristic in `docs/prompt-patterns.md` §4 corrected to match). A control arm with no guidance is mandatory — a control that does not show the failure means there is nothing to fix — plus 5+ repeats per variant, answer variance as its own metric, and every hit read by hand. With the measured caveats: on shaping failures a bare prohibition produces *more* of the unwanted thing than a recipe does, and a single nuance clause degrades a winning recipe back to noise.

- **Two disciplines for the orchestrating thread** (`rules/_generic/delegation.md`): a synthesizer spot-checks a load-bearing quote but does not re-read what its finders already read — re-investigation is how the main thread spends a delegated budget twice; and a brief states the task, not how to orchestrate it.

- **Kit files a project removes on purpose stay removed.** `.kit-manifest.json` gains an `excluded` array. `/update-kit` never adds, re-adds, merges or asks about a path listed there, and its *you deleted a kit file* row now offers **exclude** next to re-add; `/bootstrap` Phase 5.6 records every kit agent it drops. Without it a removal could not be made durable: drop the path from `files` and the next run reads it as a new kit file and re-adds it quietly, keep it and the run asks again every time. The case that surfaced it is the ordinary one — a project whose own stack-aware test agent already covers `test-writer`.

- **`/which-skill` routes to a project's own skills without a project edit to the router.** A new `## Project skills` section in `PROJECT.template.md` lists the skills a project ships next to the kit's, and `/which-skill` reads it as a second layer — route by depth, not by name, never both passes for one question. `/bootstrap` drafts the section from skills already present in `.claude/skills/`. Before this, the only way to teach the router a project skill was to paste a section into the kit-owned `SKILL.md`, which made the router a conflict on every `/update-kit`; on one project it was one of the four conflicts in a 55-commit sync.

### Changed

- **Progress tracking is file-backed and no longer prescribes a harness todo tool.** `/implement` extracts every plan step **verbatim** into a named ledger file in the session scratchpad, prints its path, and accounts for `Steps: N/N` in the final report; `/sweep`'s site inventory is the single tracker and is ticked before the next batch starts; `/tdd` writes its slice list down; `/handoff` derives "what's done" from three sources in order — the plan's step list, what the session wrote down, then the working tree — cross-checked, with anything the tree cannot confirm marked **unverified**. Two reasons, and the durable one does not depend on the harness at all: the todo tools are gated by tier and build, and the gate moves (absent outright in one Opus 5 session on 2.1.220, present as a *deferred* tool in another on that same build; `CLAUDE_CODE_ENABLE_TODO_TOOLS`, the escape hatch named in older guidance, does not exist in that binary — 0 hits against 14 for a control variable). And the list is **write-only**: there is no `TodoRead`, so nothing can read a task list back, and it could never have been a source `/handoff` derives from even where it is present.

- **`context: fork` guidance now describes background forks.** Since harness v2.1.218 a forked run is a background task by default (`background: false` opts out per skill), so its reply *does* return to the main session — as a task-notification. That is a weaker guarantee than it sounds: a notification queued while the session keeps working to its end is never drained (measured, 2 of 6 delivered), and a fork is exactly the case where the main session has something else to do. The obligation is unchanged — give the skill `Write`, name the artifact path in the body, end by saying where the file landed — but it now rests on the right reason, and the file is what survives a lost notification.

- **A plan handed to a human comes with a reading order.** `/prepare` and `/analyst` Phase 7 hand over an order optimized for early exit — intent and boundaries → requirements and ACs → steps — because a wrong problem statement means *stop reading*, everything after it is downstream of that error. With the line that earns those two minutes: the agent faithfully wrote down what you said; the most expensive finding here is what you **forgot** to say. Alongside it: a **declared** skip satisfies a stage gate and a silent one does not (`rules/_generic/planning-artifacts.md`); `/prepare` names four signals that a change is really three changes, separately from the tier table, which measures size rather than number of intents; and the story→step mapping table gains an AC column, so a story whose happy path has a step and whose expired token does not stops reading as covered.


- **The README is now a landing page, not a manual.** It opens with the copy-in block and `/bootstrap`, a "where do I start?" table, and a compact pipeline map — roughly a quarter of its former length. The long form moved to `guide/en/` and `guide/ru/`: `reference.md` (every skill, agent, rule, hook, the recommended flows, the layout), `install.md` (full walkthrough, `/update-kit`, `/teardown`), `evidence.md` (what the A/B bench measured), `why.md` (discipline layer, comparisons, distribution model). `guide/` is repo documentation and is excluded from the copy-in — the rsync command in every install snippet now carries `--exclude='guide'`.

### Fixed

- **`/update-kit` and `/bootstrap` recorded the adapted copy as the merge base, so the next update overwrote the adaptation silently.** `/update-kit` Phase 6 said to hash the *final* class-A files, and `/bootstrap` hashed rules after Phase 5 had narrowed their `paths:`. For a pristine file that is harmless; for an adapted one — a merge, a keep-mine, a narrowed rule, a filled-in hook — the next run reads *MINE == BASE*, classifies the file as untouched, and takes the kit's version over it without a question. Both now record the file **as the kit shipped it** (THEIRS on an update, the kit source on install), which keeps an adapted file on keep-mine until the kit changes it and turns that change into a real conflict. `/update-kit` also checks that every adapted file still differs from its recorded hash before writing. Found while syncing one project: six adapted files (two merged rules with project `paths:`, a newly narrowed `sql.md`, a `verify-stop.sh` with project commands, a kept `format-file.sh`, and a router with a project section) would all have been overwritten on the following update.

- **An oversized diff was truncated silently.** `/code-review` now stops and narrows explicitly — `git diff --stat` for the map, then whole files one at a time — and names in the summary what stayed unread. A truncated read loses coverage while the report still looks complete, which is the one failure mode a review cannot report on itself.

- **`verify-stop.sh` reported failures to the user but not to the model.** It now emits `hookSpecificOutput.additionalContext` alongside `systemMessage`, so a failed post-turn check reaches the agent that could act on it instead of only the human watching. Wire this hook to **`Stop` only**: measured 2026-08-21 on 2.1.220, on `SubagentStop` the harness delivers that field to the subagent that just stopped — not to the orchestrator such text addresses — and resumes that agent's turn. Warn-not-block is unchanged (`exit 0`, `decision:"block"` nowhere), and the `stop_hook_active` early exit covers the new channel too, which is not obvious given that the flag and its cap are built around *blocking* continuations: measured the same day, the Stop event ending a turn that `additionalContext` continued carries the flag `true`, so the hook speaks at most once per chain and needs no dedup state of its own.

- **`/audit-quality` told a preloaded run to write a file it cannot write.** The rubric is preloaded into the `quality-auditor` agent, which `/implement` spawns *synchronously* and continues by `SendMessage` — no fork, no notification to lose, and no `Write` declared. The REQUIRED file output now carries an explicit exception for that case, where the final message **is** the deliverable, and the neighbouring "this cannot spawn `completeness-critic`" note names the real reason in both contexts: in a fork the spawn tool errors, and inside a subagent `Agent` is stripped outright.

- **An agent's `tools:` list under-states what it gets.** Measured 2026-08-21 on 2.1.220: the harness hands `Write` and `Edit` to subagents that declare neither — including one with no preloaded skill, so it is not a union with a skill's `allowed-tools`. A `tools:` line reading `Read, Grep, Glob, Bash` states *intent*; "read-only" is enforced by the body of the prompt saying so, never by the frontmatter. `rules/_generic/delegation.md` records it next to the opposite case, where a listed tool is silently stripped.

- **A typed slash command that silently does not expand.** The harness expands a slash command only when the message *starts* with it, so a prompt pack that puts a heading or a `>`-quoted hand-off above its fenced block turns `/implement` into ordinary text: the skill never loads, nothing errors, and the session runs a lookalike procedure while both sides believe the contract is running. Fixed in the parts that ship, not only in the docs — `rules/_generic/core.md` (always-on) now tells the agent that a `/skill` present in the message with no `<command-name>` block **did not load**: name the command and let the operator re-send it, never substitute an improvised equivalent; `skills/prepare/reference/parallel-wave-execution.md` moves the session heading **outside** the fenced brief so the generated `implementation-prompts.md` starts each block with its command; and `skills/prompt-master/assets/prompt-pack-template.md` gains a fifth how-to-run rule telling the operator to copy the fence alone. `guide/{en,ru}/evidence.md` documents it as the fourth failure mode — none of the three escape hatches reaches it, because all three answer *"the user never named the skill"* and this one is the opposite — with the authoring rule also in `CONTRIBUTING.md`. Measured once, on an epic whose pack carried a note above 22 of 32 blocks: the run lost its mandatory architecture-audit phase, and the audit later returned two blocking regressions in code that had passed every acceptance check the session wrote for itself.

- **Catalog drift.** `/audit-quality`, `/deploy`, the `idea-skeptic` agent, and `docs/audience-altitude.md` shipped in 0.1.0 but were missing from the README's "What's in it" table and Layout tree (they were listed in `/which-skill` and `_kit/KIT.md` all along). All four are now in `guide/{en,ru}/reference.md`, and the 0.1.0 entry below names them too.

## [0.1.0] — 2026-08-04

First public release. Everything below is the initial contents rather than a diff.

### Added

- **The pipeline** — `/discover → /analyst → /prepare → /implement`, plus `/idea` as a plain-language front door and `/scaffold` for "add another one like the existing one".
- **49 skills** across the pipeline, orientation (`/onboard`), explore-first (`/spike`, `/prototype`, `/select-tech`), alignment and design (`/grill`, `/domain-model`, `/codebase-design`, `/api-design`), quality (`/code-review`, `/audit-quality`, `/refactor`, `/diagnose`, `/test`, `/tdd`, `/test-spec`, `/arch-health`, `/clean-mvp`, `/sweep`, `/perf`), architecture evolution (`/decompose`, `/revisit`, `/distill`), ship-and-learn (`/rollout`, `/deploy`, `/preflight`, `/incident`, `/retro`), security (`/threat-model`, `/audit-security`, `/deps`), a local backlog tracker (`/to-prd`, `/to-issues`, `/triage`, `/epic-status`, `/close-epic`), and meta skills (`/which-skill`, `/prompt-master`, `/writing-skills`).
- **16 subagents** — reviewers, the adversarial verification pair `finding-verifier` + `completeness-critic`, `plan-challenger` and `idea-skeptic`, analysis agents, writers, and `backlog-researcher`. All share one **Finding Contract**, also shipped as `schemas/finding.schema.json`.
- **14 generic rule files** in three load tiers: `core.md` alone is always-on (~950 tokens), code rules are `paths: "**/*"`-scoped, and authoring/planning rules are scoped to where they fire.
- **5 stack rule packs** — `python`, `react-ts`, `ruby`, `rails`, `postgres`.
- **8 hooks** — `guard-bash`, `guard-secrets`, `format-file`, `sessionstart`, `precompact`, `subagent-stop`, plus the opt-in, off-by-default `verify-stop` and `skill-hint`. Every hook but `guard-bash` follows the **warn-not-block** contract.
- **Lifecycle skills** — `/bootstrap` (detect stack, write `PROJECT.md`, install and reconcile rule packs, wire `CLAUDE.md` and `settings.json`), `/update-kit` (3-way merge against `.kit-manifest.json`, preserving local adaptations), `/teardown` (clean up or fully uninstall).
- **Code-publish control** — `git add`/`commit`/`merge`/`push` denied in `settings.json` and hard-blocked by `guard-bash.sh`; the agent suggests the command, you run it.
- **Docs** — `self-knowledge.md`, `decision-craft.md`, `agent-failure-modes.md`, `working-with-agents.md`, `prompt-patterns.md`, `audience-altitude.md`, `observability.md`, `agent-teams.md`.
- **English and Russian READMEs**, kept in structural parity.
- **MIT license**, and a stdlib-only structural validator (`tools/validate-kit.py`) wired into CI.

### Notes

- **The always-on tier is deliberately one file.** Three A/B rounds measured no quality gain from a larger always-on rule tier and a ~13% cost increase, so it was cut to `core.md` alone. The honest claim is *the same result for less money*, not *it works better* — the kit publishes the results that argue against it alongside the ones that don't ([guide/en/evidence.md](guide/en/evidence.md)).
- **Copy-in is the only install path.** The Claude Code plugin model carries no `rules/` component and mandatorily namespaces commands, so a plugin cannot deliver either the always-on rules or an unprefixed `/discover`. An installer plugin is the likely future addition and ships only after an end-to-end smoke test. See [Distribution model](guide/en/why.md#distribution-model).
