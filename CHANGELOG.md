# Changelog

All notable changes to FourEyes are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Because the kit is installed by copying files into a project's `.claude/`, "version" means *the kit source you copied from* — `/update-kit` reconciles a newer version against the manifest written at install time.

## [Unreleased]

## [0.2.0] — 2026-09-24

### Added

- **A board linter, so a parallel launch never rests on someone noticing that two rows claim the same file.** New `tools/lint-board.py` (stdlib-only, report-only) reads a wave board in the RUN-ORDER format and checks what a reader reliably misses: two unfinished rows whose `Owns` sets intersect with no dependency ordering them (transitively; glob against glob, segment by segment; a prose `except those N.M owns` clause honoured), dangling `Depends on` ids, cycles, a done row whose dependency is not, row↔plan status drift in both directions, a session row with no prompt and a prompt with no row, cards and plans that resolve to no file, a `Status` cell outside the vocabulary — and a board that parses to zero rows is reported as such, never as clean. `/epic-status` and `/close-epic` each gained one line: run the project's `epic:status` command first and quote it as the mechanical half of the answer. Wired per-edit by the new `hooks/lint-board.sh` (PostToolUse, path-filtered in shell so ordinary edits never start an interpreter) and per-session by the `__BOOTSTRAP_EPIC_STATUS__` region that was already waiting in `sessionstart.sh`. The check that motivated it found a real collision on a live 22-row board that neither `/prepare` nor an operational pass had seen.

- **A dead-reference gate for the project's own instructions.** New `tools/lint-refs.py`: every repo path `CLAUDE.md` and the files under `.claude/` cite, in backticks or as a markdown link, must still exist — an agent sent to a "reference implementation" that was renamed away follows a dead end, and nothing else in the build fails when that rots. Kit-owned files are skipped via `.kit-manifest.json` (their example paths are illustrations, and `/update-kit` owns them), as are placeholders, globs and the local-only trees named in `PROJECT.md`. A path cited on purpose — a rule naming a layer that must *not* exist — goes into `.lint-refs-baseline` once, and a baseline entry that stops matching is reported, so the file only shrinks. `/preflight`'s docs-drift step runs it. On one real project the equivalent found 5 genuine dead references out of 493, including two rules contradicting each other about the same directory.

- **`/audit-quality` Check 11 — prose as a claim about the code**, plus `docs/claims-audit-patterns.md`, which works the same ground as fourteen named patterns for when a finding does not fit the check's six bullets. Checks 1–10 read the code; this one re-derives the sentences *about* it: grep the rule as prose rather than as the symbol (the symbol finds the code, never its twin sentence), a completed enumeration must not carry a quantifier, a constant changed by more than ~2× invalidates the numberless premise beside it, comparatives name both populations, an absolute guarantee is read against the producer's non-happy branches, and "now redundant" / "0 live today" is a licence to delete that someone will use. Mined from a 287-entry agent-memory corpus where ~60 of 109 stack-neutral lessons were this class and the single most repeated one occurred 43 times, against zero checks for it in the kit. `agents/finding-verifier.md` gained the matching qualifier: the classic comment false positive is a *behavioural* finding evidenced only by a comment — a finding about the **comment's own truth** is a real defect of its own class.

- **A re-check-round checklist in `agents/quality-auditor.md`.** Six independent memory entries record the *fixing* round creating the next instance of the defect it closed, so a re-check now re-runs lint and the formatter over the changed set (actually runs them), measures size headroom itself and treats zero slack as a finding, re-greps the prose of every rule the fix touched **including outside its own file list** (read and report, never edit), treats the fix's own new sentences as new claims, and hands back a query rather than a list for any set it names.

- **Memory gets a shape, and `/retro` finally reads it.** `rules/_generic/memory.md` now specifies three fixed index sections (*Recurring — check first* / *Sanctioned — do not re-flag* / *Method lessons*), an `(N×)` counter on the index line with one dated occurrence per hit in the file, a per-entry size cap, and `(1×)` candidates that are allowed but pruned if they never recur. `/retro` Phase 1 adds `.claude/agent-memory/**` — every tree, since stores fragment by the session's cwd — and an entry at `(≥3×)` is a promotion candidate by definition: routed to a rule, agent stance or skill step, then compressed to a pointer. `docs/working-with-agents.md` gained the cwd-fragmentation warning (measured on one project: four trees, the root index knowing about ~90 of 287 entries).

- **Five test antipatterns that read as coverage** (`rules/_generic/testing.md`, mirrored as a probe in `agents/test-gap-finder.md`): an assertion over a degenerate fixture, a check that walks a set with no floor on the set, a thread-through test entered at the outermost function, a fixture placed away from the threshold it exercises, and an expectation derived from the same table the code reads. Each row names the mutation that should turn the test red.

- **`agents/plan-challenger.md` gained a sixth challenge — `Verify:` discrimination.** A gate that passes *before* the step is no gate, and it is now a **GAP** rather than a NOTE: scope to the symbol not the file, never quote text a formatter can re-wrap, and an ordering check names an artifact the same function emits. `agents/plan-verifier.md` reads the direction of the plan's own diff (a planning extension is not evidence of implementation), diffs `Owns` against the working tree in both directions including the suggested commit block, and resolves sibling findings by symbol rather than by an ordinal that gets renumbered between revisions.

- **`/close-epic` proposes a path-scoped invariants rule when a silent class repeats.** Two findings of one silent class — money, time, access — in a single epic means the codebase has a place where wrongness does not announce itself, and the next person will land in it too. New `skills/close-epic/assets/invariants-rule.md`: narrow `paths:`, a "why this class is silent" paragraph, numbered invariants each pointing at the symbol that owns it, and a severity table. Every line must be a violation that actually happened and was fixed.

- **Every executing skill writes its log back to the plan or card it was handed, not only to chat.** New `skills/implement/reference/work-log.md` generalises `/implement`'s Implementation Log into one contract that `/diagnose`, `/test`, `/test-spec`, `/refactor`, `/tdd`, `/perf`, `/clean-mvp` and `/sweep` now follow whenever `$ARGUMENTS` or a session brief names a planning artifact. The contract has five parts. (1) A ledger lives on disk from the first phase. (2) Each deviation is recorded with `Decided by` at the moment it is decided. (3) A dated `## <Skill> Log` section is appended, never overwritten, with Result · Changes made · Deviations · Verification · **Re-check later** · Findings not fixed here · Out-of-scope edits. (4) Status goes in the frontmatter, or in the log heading when the file has none. (5) The artifact is added to the commit suggestion. `Re-check later` is the section built for what gets lost: every check the session could not observe itself (a post-deploy log grep, a 24-hour count, a query after N events, a UI gesture) gets its command, a dated baseline captured now, and a pass condition. A bare description still gets the old suggest-only behaviour. The failure it fixes was measured on one project: in one parallel wave, six `/diagnose` sessions each fixed a card and left zero on-disk logs, so the close-out had only commit subjects to verify against, and the post-deploy checks those sessions could not run survived only in their transcripts. `rules/_generic/planning-artifacts.md` names the contract.

- **`/close-epic` now checks docs drift in the direction that actually rots: what the epic *added*.** A reference checker only verifies that mentioned things exist, so a module, command, dependency or invariant mentioned **nowhere** is invisible to it and scores as a clean pass — and in this kit the thing left stale is `.claude/PROJECT.md`, which every other skill reads first, so the cost is mis-routed future sessions rather than a wrong sentence. Phase 4b derives the delta from the epic's own commits, greps each new public name against the profile, the rules and the docs, and maps the finding to the artifact that owns it (Architecture, Canonical exemplars + wiring proof, Commands, Stack / Integrations, Deploy mapping, the glossary). One-line syncs land under the inline allowlist; **authoring a rule does not** — a rule is a claim about the whole repo argued from occurrences across it, and the close-out has read one epic, so it becomes a card routed to `/distill`, `/retro` or `/bootstrap`. The negative result is a reported row: "N surfaces checked, all present" is evidence, silence is indistinguishable from a skipped step. Measured on one project with the CLI-verb variant of the check: 2 of 38 registered commands had zero mentions across its rules, docs and root instructions.

- **`/close-epic` takes a batch, and leaves a board instead of chat text.** One invocation now accepts several epics: a *wave-batch* (one RUN-ORDER cutting across directories) still prices as one unit, while a *close-batch* of independent epics is tiered, verified, ledger-rowed and archived per epic under one run-level agent budget (≤8 live / ~12 spawned, one completeness critic for the whole set, mandatory `TaskOutput` collection). Two failures it closes: an unreadable plan status is now a straggler rather than a silent pass, and an epic named in the invocation but missing from the summary table is a reported non-close. Small documentation debt — dead refs, comments the epic's own diff falsified, typos in its plans — is fixed inline under a ≤15-line allowlist that explicitly excludes source behaviour, because a one-line bug fix at close is unreviewed, unowned, and buried in an archive commit. What survives the worth-it gate is **written to disk as a runnable epic** — `<topic>-followups/` with a board, one card per item, and session prompts — never proposed as chat text. Every card names its route (`/implement` · `/prepare` · `/diagnose` · `/analyst` · `/spike`) **and its `rec: <model>/<effort>`**, the same value in three places (card header, board `Rec` column, session heading), scored on `/prepare`'s shared complexity table plus its risk overlay rather than invented per file, with two close-out-specific calls the shared rubric does not make: a drive/measurement card is priced on how easy it is to fool yourself rather than on diff size, and a record-correction card is only mechanical until it re-points a grep other files pin. The prompt format is `/prepare`'s per-session brief rather than a lighter one of the board's own: the `## Execution Order` map is how parallelism gets stated (`W1: [01 ∥ 02] → W2: [03]`), `Solo: YES` carries its reason, `DO NOT TOUCH` is annotated `[NN · concurrent|future|merged]`, and the slash command stays the first line inside the fence — so two cards packed into one session get two blocks pasted as two messages, never one block with two commands, of which only the first would expand. Sessions are packed to the context budget. Measured on one project's history: 10 of 14 close-out sessions were immediately followed by the operator asking for exactly that artifact by hand. New `skills/close-epic/reference/followups.md` carries the tier; `Write` joins the skill's `allowed-tools`.

- **The worth-it gate defaults to *not* filing a card, and a board must clear a debt-stock check before it may exist.** Every finding gets exactly one of four dispositions — card · gated card · a named `known-undone` clause in the ledger row · dropped-with-evidence, with `finding-verifier` on anything the session did not observe itself — and the default is the `known-undone` clause. A row leaves it only by carrying a consequence sentence — `<class> · <who bears it> · <what goes wrong and by when>` — with the class from a closed list (data/money loss · a wrong number on a production path · user-visible breakage · shipped code with an unobserved verification · a blocked successor), and an explicit never-card list covers doc drift, stale tallies, tooling-vocabulary gaps, dev-tool test debt and rule polish argued from one epic. That sentence is a mechanical stand-in for a skeptic, because the session applying the gate is the session that authored the findings — `finding-verifier` rules on truth and never on worth, which is exactly the hole an operator post-mortem named: *"the worth-it gate failed because the author of the findings applied it to their own findings."* The failure mode it is priced against: a criterion a card can always meet — "something breaks **or misleads** if it is never done", and a stale comment misleads by definition — makes a card the cheapest outcome to argue for, and a close-out then spawns boards of its own size. Measured on one project, a chain **four generations deep** (feature epic → follow-ups → a successor epic → a residuals board), **8 open boards / 30 cards / 21 never started** at the moment a ninth was being authored, with five boards untouched for 46 / 15 / 14 / 5 / 5 days. So supply is gated on stock: ≥3 open follow-up boards, any board untouched >14 days, or an epic that is itself generation ≥2 → the run authors **no new board**, and survivors append to an open board, get parked with a trigger, or land in the ledger row; the stock line is reported with denominators whether or not a card is filed. Capping containers would not have caught that — 3 boards × 8 cards is twenty-four sessions. And **one approval line goes out before any file is written** — `NN <slug> · <class> · <route> · <rec>`, one line per card; the board is still authored on disk once the user says go, so this confirms *contents*, it is not a return to proposing boards as chat text. Filing zero cards and naming six known-undone clauses is a correct run, and the completeness critic's gaps are priced by the gate rather than each demanding a disposition above `known-undone` — the critic hunts absences and cannot price them, and most price at zero.

- **A path-keyed small-debt register, so the rows nobody cards land where a session will actually meet them.** A ledger clause is a verdict-index entry nobody opens looking for work, so a row whose fix fits a **ride-along** — ≲10 lines, written down in full — goes instead to a register keyed by path: new `skills/close-epic/assets/small-debt-register.md` ships the contract as an installable template, its location is a `PROJECT.md` field that `/bootstrap` asks for, the file itself is created on first use, and `rules/_generic/code.md` tells a session about to edit a file to grep the register and take its rows in the same diff. Anything too big for a ride-along stays a named known-undone clause, which is the honest artifact for real work nobody is scheduling. The register's contract is deliberately hostile to becoming a queue: rows are verified before filing, the fix is written out so nobody re-derives it, a row unclaimed for 90 days is deleted with its reason, and **no row count triggers anything** — a sweep fires on the operator's word only, boxed to docs/comments/anchors with every row re-verified first, because rows rot and a sweep that fixes without re-reading writes new drift over old. Measured on one project: an audit residue treated as a queue became a nine-plan epic, the rows having been cheap only while their files were already open.

- **Decision provenance on the review path.** A `/implement` deviation row now carries a fourth field, `Decided by`: `[AGENT]` unless the user's own words are pasted **verbatim**, in the language they wrote them, at the moment they answer — paraphrase, translation, and "the user approved this" are `[AGENT]`. The quote travels into the plan's `## Implementation Log` and into both Deviation Report tables, and `/code-review` Phase 1 opens by listing the decisions the diff embodies, reading the tag off that artifact cell rather than off memory: no quote, no `[USER]`. A review runs on the diff in a fresh session where the build conversation no longer exists, so the cell is the only evidence a decision was ever the user's — an agent that "remembers" one is precisely what the tag exists to catch.

- **Scenarios and numbers on acceptance criteria.** An AC that touches state, money, authorization, or an external contract now carries a named `GIVEN/WHEN/THEN` scenario (`/analyst` Phase 6 and `skills/analyst/assets/spec-template.md`), with the header naming the case and never its number; elsewhere it stays prose. ACs are quantified wherever the thing is measurable — "fast", "reliable", "handles large inputs" are not criteria until they carry a number and a unit — and `/grill` hunts those words as a lens rather than a checklist. One rule is one observable behavior: a line that needs an "and also" to finish is two rules. Left vague, the number is decided silently by whoever writes the code.

- **A verification-gap lens, and a stricter definition of "tested".** `/code-review` Phase 2 asks one added question: if the behavior the change was made for broke *where it is actually used*, would verification fail? `rules/_generic/testing.md` names the common way it would not — a test that exists but never ran (unregistered, filtered out, skipped, disabled) counts as missing, not as coverage, because a green suite that never executed the case reads exactly like a passing one.

- **A cap on the fix-and-re-audit loop.** `/implement`'s architecture audit stops after 3 rounds. "Re-audit until every modified file passes" has no stopping condition when auditor and implementer simply disagree; at the cap every open finding gets a named row, the plan goes to IN-PROGRESS, and the user decides. Continuing the *same* auditor rather than spawning a fresh one is unchanged.

- **A micro-test protocol for behavioral wording** (`skills/writing-skills`, with the heuristic in `docs/prompt-patterns.md` §4 corrected to match). A control arm with no guidance is mandatory — a control that does not show the failure means there is nothing to fix — plus 5+ repeats per variant, answer variance as its own metric, and every hit read by hand. With the measured caveats: on shaping failures a bare prohibition produces *more* of the unwanted thing than a recipe does, and a single nuance clause degrades a winning recipe back to noise.

- **Two disciplines for the orchestrating thread** (`rules/_generic/delegation.md`): a synthesizer spot-checks a load-bearing quote but does not re-read what its finders already read — re-investigation is how the main thread spends a delegated budget twice; and a brief states the task, not how to orchestrate it.

- **Kit files a project removes on purpose stay removed.** `.kit-manifest.json` gains an `excluded` array. `/update-kit` never adds, re-adds, merges or asks about a path listed there, and its *you deleted a kit file* row now offers **exclude** next to re-add; `/bootstrap` Phase 5.6 records every kit agent it drops. Without it a removal could not be made durable: drop the path from `files` and the next run reads it as a new kit file and re-adds it quietly, keep it and the run asks again every time. The case that surfaced it is the ordinary one — a project whose own stack-aware test agent already covers `test-writer`.

- **`/which-skill` routes to a project's own skills without a project edit to the router.** A new `## Project skills` section in `PROJECT.template.md` lists the skills a project ships next to the kit's, and `/which-skill` reads it as a second layer — route by depth, not by name, never both passes for one question. `/bootstrap` drafts the section from skills already present in `.claude/skills/`. Before this, the only way to teach the router a project skill was to paste a section into the kit-owned `SKILL.md`, which made the router a conflict on every `/update-kit`; on one project it was one of the four conflicts in a 55-commit sync.

- **An engine-independent SQL rule.** New `rules/_generic/sql.md`, scoped to SQL, migration, model, repository and query paths: an index is owned by a named query and taxes every write; "the index is used" proves nothing until each WHERE condition is classified as an access or a filter predicate; a function or cast on the column hides its index; `(col = :p OR :p IS NULL)` forces a full scan; paginate by keyset, never OFFSET; a loop of queries is a correctness bug before a performance one; read-check-then-write is a race that snapshot isolation does not catch; a generated primary key guards nothing without a natural key; a schemaless column moves the schema into code. The stack pack still carries the engine. `/bootstrap` re-scopes the template globs to where the project actually writes SQL — replacing them, not narrowing them, when SQL lives in ordinary application modules — and `/update-kit` asks for the same re-scoping when the rule arrives in an existing install. The generic layer is now 15 files.

- **A visual-hierarchy and accessibility rule for the `react-ts` pack.** New `ui-visual-hierarchy.md` on `*.tsx` / `*.css`, limited to checks that can be read off markup and class names without rendering: tokens for spacing, type and colour, with the second hand-tuned arbitrary value as the trigger; `Label: value` pairs that flatten hierarchy; spacing that must separate groups more than it separates members; container queries over percentage widths; one column per sortable field; `alt`, labels and accessible names; heading levels that never skip; real buttons and links with a visible focus style; contrast of at least 4.5:1, without buying it through opacity on white.

- **`/codebase-design` answers *when* to cut and *what shape* to cut, not only *where*.** New `WHEN-TO-CUT.md` is read before any new seam. It asks whether the cut is due: can the interface be written as a few calls, do the parts differ in rate of change, reason for change and the actor who asks for it, and where is fan-in × churn highest. It then asks for proof that the boundary is real: an enabling point outside the code, a port declared by its caller, a deletion test, a named mechanism that enforces the direction, a writer census per table. The price comes before the benefit, co-location is a legitimate outcome, and a data section sizes consistency boundaries by the staleness deadline the domain states, names orchestration / shared data / events as three distinct joins, and gives derived data a rebuild procedure and a reconciliation job. New `SHAPE.md` covers the form behind the seam: a function by default and a class only for a capability a function lacks, class or transform decided by mutability, decide-then-do, inheritance under two named conditions rather than a slogan, messages before classes, a pattern priced in the units of its benefit, and "how would I test this?" asked before any test exists. `DEEPENING.md` gains the divergent-change, shotgun-surgery, reaching-chain, ambiguous-choice-point and logic-in-the-shell smells, plus moves for cutting by field use and breaking import cycles. `DESIGN-IT-TWICE.md` writes the caller's code first, adds change-cost, prevention-vs-detection and what-it-makes-hard as comparison axes, and treats a named solved mechanism (rate limiting, ID generation, cache eviction) as a closed set of standard algorithms to pick from, not a space in which to invent design B.

- **`/select-tech` has a gated companion for anything that holds or moves state.** New `STORES-AND-TRANSPORTS.md`: name one non-database option before the shortlist, ask who writes to the store (several independently deployed writers make it an integration database), price every added store as a recurring bill, derive the class from volume, access shape, read:write ratio and demanded consistency before naming a product, let the relational default win ties, price isolation levels, last-write-wins and two-phase commit against a processed-message-id table, decide erasure and querying before the first event is sourced, and walk the transport ladder from request/response upward. Phase 1 now solves the problem with the incumbent in writing before any candidate is named, tiers candidates by invasiveness, spends one shared novelty budget for the whole design, and judges against the project's full set of problems. Each finalist gets an enumerated failure-mode list and an operating bill, and a storage model is called out as the one-way door an adapter seam cannot make reversible.

- **Legacy fallbacks for `/refactor` and `/test`.** New `skills/refactor/LEGACY.md` is for a unit that will not go under a test harness. It breaks the "no tests, so write tests first" deadlock in a fixed order: conservative dependency-breaking only, then characterization tests, then the change. It also covers partial coverage ranked by how long an error would stay hidden, extraction by coupling count, and sprout and wrap as priced debt. New `skills/test/reference/legacy-mode.md` loads when the target has no tests and nothing states what it should do. It pins observed behaviour, including behaviour marked as suspicious, and places the test at the nearest point where the effect is observable, or at the narrowing point that several collaborating units funnel through.

- **`docs/decision-craft.md` §9–§13.** §9, the operating list: fourteen things every operated component needs, walked per finalist to price the marginal cost of a technology, and read backwards by `/incident`. §10: build-time vs run-time complexity. §11: compensation is not a rollback. It has no isolation, the compensating write can fail, and the user ends up waiting on someone else's step, so prefer recorded workflow state. §12: a principle cited without its limit is not an argument. §13: every option has two prices, the one to build it and the one to carry it. §1 adds that the two door errors are asymmetric, that reversibility is priced by blast radius, that rate is part of reversibility for automation that destroys, and that reversibility bought is not reversibility used until someone has named the trigger.

- **`/decompose` can return MERGE, and some drivers are vetoed.** A boundary that already exists and is wrong — co-change, lockstep deploys, a shared transaction — gets a MERGE verdict routed to `/rollout`. Atomicity, a consistent read across both sides, and a customer-operated deployment veto EXTRACT whatever the drivers say. Every candidate names the axis of the cut (abstraction, subdomain or instances), the boring alternative for each driver, the connection budget, and the remainder left behind in one sentence without "and".

- **Two new agent failure modes** in `docs/agent-failure-modes.md`. #23 is the judge's thumb on the scale: self-preference, position and length bias when one model scores its own output. #24 is retrieved text read as an instruction. The authoring notes add that every gate has two failure rates, and that a run where every gate is green and the outcome is still wrong must name the gate wording that passed.

### Changed

- **Six generic rules stop overruling deliberate project architecture.** A consumer audit compared each project rule with the generic rules that load in the same session and found places where a `**/*` rule contradicted a design the project chose on purpose — so an agent received both and could "fix" correct code toward the generic one. `service-layer.md`: a module is not a consistency boundary by itself, a composer layer the project declares may write several modules in one transaction on one store, and writes across stores are sequenced with compensation or joined by an event; a command returning its own outcome or the id it wrote is a receipt, not a query. `exception-patterns.md`: a project that returns result objects by convention keeps them, provided every caller branches on the outcome. `domain-events.md`: an outbox buys atomicity only inside the state's own store — otherwise enqueue after commit and name the loss window. `code.md`: a project comment rule overrides the comments section, a TODO carries the condition that retires it, and the no-planning-labels rule covers rules and docs as well as code. `code-quality.md`: comment density follows the project's comment rule. `testing.md`: a test name may be a sentence or an identifier and the stack's established shape wins; a UI test's wait helper counts as setup; an automatic retry only captures a trace, and a pass on retry is flaky. Every file stays inside its character ceiling — the nine-file layer went from 43,977 to 43,813 characters, paid for by removing examples that restated the bullet above them.

- **Progress tracking is file-backed and no longer prescribes a harness todo tool.** `/implement` extracts every plan step **verbatim** into a named ledger file in the session scratchpad, prints its path, and accounts for `Steps: N/N` in the final report; `/sweep`'s site inventory is the single tracker and is ticked before the next batch starts; `/tdd` writes its slice list down; `/handoff` derives "what's done" from three sources in order — the plan's step list, what the session wrote down, then the working tree — cross-checked, with anything the tree cannot confirm marked **unverified**. Two reasons, and the durable one does not depend on the harness at all: the todo tools are gated by tier and build, and the gate moves (absent outright in one Opus 5 session on 2.1.220, present as a *deferred* tool in another on that same build; `CLAUDE_CODE_ENABLE_TODO_TOOLS`, the escape hatch named in older guidance, does not exist in that binary — 0 hits against 14 for a control variable). And the list is **write-only**: there is no `TodoRead`, so nothing can read a task list back, and it could never have been a source `/handoff` derives from even where it is present.

- **`context: fork` guidance now describes background forks.** Since harness v2.1.218 a forked run is a background task by default (`background: false` opts out per skill), so its reply *does* return to the main session — as a task-notification. That is a weaker guarantee than it sounds: a notification queued while the session keeps working to its end is never drained (measured, 2 of 6 delivered), and a fork is exactly the case where the main session has something else to do. The obligation is unchanged — give the skill `Write`, name the artifact path in the body, end by saying where the file landed — but it now rests on the right reason, and the file is what survives a lost notification.

- **A plan handed to a human comes with a reading order.** `/prepare` and `/analyst` Phase 7 hand over an order optimized for early exit — intent and boundaries → requirements and ACs → steps — because a wrong problem statement means *stop reading*, everything after it is downstream of that error. With the line that earns those two minutes: the agent faithfully wrote down what you said; the most expensive finding here is what you **forgot** to say. Alongside it: a **declared** skip satisfies a stage gate and a silent one does not (`rules/_generic/planning-artifacts.md`); `/prepare` names four signals that a change is really three changes, separately from the tier table, which measures size rather than number of intents; and the story→step mapping table gains an AC column, so a story whose happy path has a step and whose expired token does not stops reading as covered.


- **The README is now a landing page, not a manual.** It opens with the copy-in block and `/bootstrap`, a "where do I start?" table, and a compact pipeline map — roughly a quarter of its former length. The long form moved to `guide/en/` and `guide/ru/`: `reference.md` (every skill, agent, rule, hook, the recommended flows, the layout), `install.md` (full walkthrough, `/update-kit`, `/teardown`), `evidence.md` (what the A/B bench measured), `why.md` (discipline layer, comparisons, distribution model). `guide/` is repo documentation and is excluded from the copy-in — the rsync command in every install snippet now carries `--exclude='guide'`.

- **`_kit/templates/commands/commit.md`** — the house style read from `git log` now wins over the Conventional Commits default instead of contradicting it; staging is by explicit path only (never `-A`, `.` or a directory); the file set is what *this session* touched, with everything else listed as left out, because parallel sessions share one working tree; and the message describes the change alone — no plan, card or wave identifiers.

- **`/distill` measures before splitting a rule's examples into an on-demand reference.** Fenced examples are a smaller share of a rule's weight than they look: measured across one project's heavy rules, 5–16 %, so moving all of them bought ~10 KB off a 116 KB autoload in exchange for two files and a link to keep true. Prose, not examples, is what makes a rule heavy.

- **`/grill` is model-invocable, and asks better questions.** Arch-health, prototype, decompose and prepare all instruct the model to "`/grill` it", but a skill carrying `disable-model-invocation` cannot be reached through the `Skill` tool, so every one of those lines was a dead end. The flag is gone. The cost is 779 characters of always-on listing budget, and the manual-by-default count is now 41 of 49. The interview itself now turns a preference question into an answerable one and resolves an ambiguous rule with a case and its neighbour just past the boundary. It separates technical forks from business trade-offs, asks for the behaviour that proves a practice rather than whether it is "in place", treats "saga" as a problem statement, pins words with two meanings, ranks competing goals before challenging scope, separates shape from scope, records a tripwire on each material fork, and ends with disagree-and-commit.

- **`/analyst` and `/prepare` price the problem before the solution.** `/analyst` takes scale as dated numbers rather than adjectives. It asks where the advantage comes from, in reverse so that not everything comes back as core, and checks the declared architecture against the as-built one. It walks an unfamiliar domain through events before entities, finds the transaction boundary by asking what happens if only one step fails, and asks who outside the repository reads data whose shape or owner is changing. `/prepare`'s alternatives table opens with a least-machinery Row A that later rows must beat at a named failure point, and adds two rungs that usually get skipped: delegate to a layer you already run, and cordon off. Each row carries a prerequisite, a failure-branch score and an undo mechanism in place of "easy/hard". Before any component is named, the plan does the arithmetic, multiplies availability across synchronous hops, and caps the driving characteristics at three. The impact analysis gains co-change and mutation as sources of ripple, a downtime line per moving part, readers outside the repository, and a price and bound for any autonomous loop. A production-visibility check asks for the query that will be run after deploy.

- **Planning and core rules carry detection, not only intent.** `core.md`: reversible means naming both the undo and the signal that would prompt it; a structural finding is written as a trade-off with a named loser; confusion is a finding about the artifact. `planning-artifacts.md`: an artifact that must stay current names who updates it and on what trigger; a finished plan is handed to a context-free reader for a cold-reader check; new technology enters as a priced decision, never through an implementation diff; every option carries two prices.

- **The generic code rules got sharper edges.** `service-layer.md`: one use case, one consistency boundary, one transaction, and command/query separation judged by *observable* side effects. `code.md`: guard a read-then-write pair; mandatory comments on deliberate deviations and tuned constants, and a rename where a comment only excuses a name; enforce each rule where its churn says. `code-quality.md`: a size limit is a tripwire, not a verdict; a precise definition of a flag argument (a literal at every caller and a branch in the body, enums included); extraction addressed by comments; a pattern only once the language feature that already does its job has been named; duplication counted by reason for change. `domain-events.md` names the dual write and moves out-of-process events to an outbox. `exception-patterns.md` gives every asynchronous failure a destination. `external-api-integration.md` parses tolerantly and checks what actually arrived. `observability.md` logs only what is impure, logs where the intent was decided, and makes ERROR mean an operator must act. `resilience.md` bounds every blocking wait rather than only network calls, budgets the whole chain against the caller's deadline, forbids chained blocking calls, opens breakers on fault density rather than a consecutive count, bounds queues and processed-id sets, and passes a retry the value from trigger time.

- **Testing discipline tightened across the rule and the skills.** `testing.md`, `/test`, `/tdd` and `test-writer`: mock only unmanaged out-of-process dependencies and run managed ones for real. A double you own passes the role's contract test. Test names state a behaviour fact in domain words. A new test must be seen red. Computed expectations, test-mode branches and assertion helpers are antipatterns. Test edits have a direction, and removals need justification. `/test` replaces coverage percentages with a two-axis verdict (complexity × collaborators), gives each scenario exactly one integration test on its longest happy path, and adds a two-half contract test for provider clients. Painful mock setup is read as a report about the design. `/tdd` gains a red-bar protocol (two failed GREEN attempts stop the edits), two GREEN gears, cheapest-first slice ordering starting from the degenerate case, a row that only closes after REFACTOR has removed the test-to-code duplication, and a closing gate that writes the dumbest passing implementation to find missing cases.

- **`/refactor` verdicts every candidate before touching it.** FIRST / AFTER / LATER / NEVER, and only the first two are applied. Tests run after every step and never from a red bar. A step that reddens without an obvious cause is reverted and redone smaller. A wrong abstraction is undone by inlining it into every caller. Guard-clause flattening and override deletion are flagged as behaviour changes where they are. The report states what the pass cost as well as what it bought. `/implement` shares the red-bar discipline, pins untested callees one level deep, stops at the third deviation row, and adds guidance for choices the plan left open (where an error is handled, jitter on shared schedules).

- **`/arch-health` ranks on history, not only on shape.** A co-change probe over six months of history, with guards against sweeps, hub files and pairs coupled by construction, reports pairs across declared boundaries that no import explains. Traffic is now a ranking axis beside leverage and cost, and cold modules move to a dated `Parked` line. Every finding that would remove a seam carries an `ignore-if` line and the grep behind it. Findings are classified (accidental requirement or competitive core), name the force acting on the code, and may end as *accepted, priced*. There is a downtime map and no REWRITE verdict. `arch-tracer` flags calls that bypass the domain even when the graph stays acyclic, and `audit-quality` asks whether a second variant is actually coming before reporting weak extensibility.

- **ADRs and glossaries record what a decision obliges.** `ADR-FORMAT.md` gains Assumptions (how the requirement is most likely to shift) and Compliance (the test, lint or review that guards the decision). Consequences separate owed work from drawbacks and carry one line of business ground. Technology chosen to hold up a non-functional characteristic now counts as ADR-worthy. `CONTEXT-FORMAT.md` distinguishes a homonym from a synonym (`_Same word, other context_`), and `/domain-model` splits a kind from its instances and gives each context its own renamed model.

- **`/rollout` and `/sweep` stage data moves.** Expansion is only what the running code cannot see. A value stored as data (status strings, event type names, routing keys) is renamed with expand–contract, not a find-replace, and `/sweep` routes that half to `/rollout`. Writers and readers are inventoried separately. Replicate-back and parallel run are named options with their prices. Behaviour is frozen mid-migration, so a fix lands in both paths or waits. Code ships before the data migrates, and trickle-then-batch is preferred over one big backfill. A canary is only worth as much as the signal under it.

- **`/api-design` sets the promise per edge, and designs for agent callers.** A contract can be loose toward a client that ships with it and versioned toward one that releases on someone else's clock. A breaking change is defined by subset and superset rules, so adding validation to a field that never had any is breaking. When an LLM agent is a consumer, the unit of the contract is a completed step of work rather than a resource row, responses lead with what the caller can act on, and the endpoints deliberately *not* exposed are documented too. The decision table adds read-after-write staleness, size bounds beyond pagination, currency paired with every amount, documented refusals with `Retry-After`, and the careless-client check.

- **`/diagnose`, `/perf` and `/incident` vary before they read.** `/diagnose` re-runs the reproduction with deliberate TINY and LARGE variations and treats each reported condition as a hypothesis to strip. It isolates a partial failure by dimension, names the defect class so siblings spelled differently are found, and carries "delete code" as a hypothesis. `/perf` separates throughput, response time and responsiveness. It computes the floor before profiling, profiles the critical path of a graph, keeps batching in the effect layer, requires every accumulator to name what reclaims it, and ranks fast failure above slow success. `performance-analyzer` flags counters updated in place on a hot row. `/incident` treats a trail that ends at a person as missing information or a dangerous tool, and gives alerts two conditions to earn a page.

- **Review, audit and exploration skills tightened.** `/code-review` and `code-reviewer` name the mechanism behind a feeling, accept "I cannot hold this in my head" as a finding, judge legibility before reading the explanation, and treat a notice as no mitigation. Four checks cover what naming rules cannot see: one name used for two concepts, conditionals that stand in for a missing type, an abstraction that does not pay for itself, and a public entry point that fails open when misread. `/audit-quality` states the inheritance conditions, catches retries that fire a day later on moved state, and requires idempotency guards enforced at the write. `/audit-security` adds output encoding (`#xss`). `/spike` builds at least one hard case and walks a concurrency ladder. `/prototype` checks each UI variation's hierarchy, hover-only affordances and contrast before showing it. `/onboard` marks trace hops observed or inferred and filters churn with a reason for each hotspot. `/revisit` no longer treats a list of a tool's defects as a broken assumption. `/deps` holds a direct dependency whose upstream has stopped, but never on age alone.

- **Authoring guidance measures its own resolution.** `/writing-skills` requires naming the closest existing skill before adding one, checks names against built-in commands, states what a run count can detect (about 10 runs per arm for a 30-point gap, about 100 for a 10-point one), keeps a held-out case, and accepts either a micro-test or a named failure as evidence for new wording. `docs/prompt-patterns.md` treats example order and proportion as instructions, verdict levels spelled out in words, every included snippet as something that will be used, and a prompt-level STOP as a reminder unless a structural gate enforces it. `delegation.md` reads a subagent's call histogram as evidence about its brief. `/distill` moves mechanically decidable conventions into automation.

- **Stack packs.** `postgres`: indexes and HOT updates, index direction and NULLS order, BRIN preconditions, index-only scans that depend on the visibility map, SERIALIZABLE as a property of the whole workload, function volatility, the vacuum horizon held by long transactions, the fair lock queue and `lock_timeout` on DDL, session advisory locks leaking through the pool, fencing tokens, `LISTEN/NOTIFY` as a hint rather than a queue, batched backfills, and query-equivalence checks before timing a rewrite. `ruby` / `rails`: guards declared with `except:` so new actions inherit them (and the inverse polarity for `skip_before_action`), schema-shaped models, unbounded eager loading, refused bequest, check-then-write as a race, and `counter_cache` on a hot parent. `python`: a generator's `finally` is not a cleanup guarantee, exception roots at package boundaries, `assert` stripped under `-O`, the precise flag-argument definition, and `T | None` only where `None` cannot collide with a falsey result.

- **`docs/observability.md` is now a product-observability page.** It covers the wide event with an attribute catalogue (identity, version, flags, timing, downstream, actor, budget, outcome), span shaping, event-based SLIs with eligibility and success filters, and signals for an LLM feature. The Claude Code OpenTelemetry section is replaced by a link to the official docs. `observability.md` separates metric-label cardinality (keep it low) from event cardinality (keep the ids), and `/prepare`, `/rollout`, `/diagnose` and `/incident` each gained a visibility check.

- **Kit text names no books or authors.** Rule and skill headers that cited titles and authors now describe the principle in the kit's own voice. `/writing-skills` makes this a house convention: ideas are rewritten for the moment the agent applies them, pattern names such as Strangler Fig are fine, and attribution lives outside the published kit. The `/analyst` spec template no longer ships an `Author:` line naming the skill.

### Fixed

- **`/update-kit` and `/bootstrap` recorded the adapted copy as the merge base, so the next update overwrote the adaptation silently.** `/update-kit` Phase 6 said to hash the *final* class-A files, and `/bootstrap` hashed rules after Phase 5 had narrowed their `paths:`. For a pristine file that is harmless; for an adapted one — a merge, a keep-mine, a narrowed rule, a filled-in hook — the next run reads *MINE == BASE*, classifies the file as untouched, and takes the kit's version over it without a question. Both now record the file **as the kit shipped it** (THEIRS on an update, the kit source on install), which keeps an adapted file on keep-mine until the kit changes it and turns that change into a real conflict. `/update-kit` also checks that every adapted file still differs from its recorded hash before writing. Found while syncing one project: six adapted files (two merged rules with project `paths:`, a newly narrowed `sql.md`, a `verify-stop.sh` with project commands, a kept `format-file.sh`, and a router with a project section) would all have been overwritten on the following update.

- **An oversized diff was truncated silently.** `/code-review` now stops and narrows explicitly — `git diff --stat` for the map, then whole files one at a time — and names in the summary what stayed unread. A truncated read loses coverage while the report still looks complete, which is the one failure mode a review cannot report on itself.

- **`verify-stop.sh` reported failures to the user but not to the model.** It now emits `hookSpecificOutput.additionalContext` alongside `systemMessage`, so a failed post-turn check reaches the agent that could act on it instead of only the human watching. Wire this hook to **`Stop` only**: measured 2026-08-21 on 2.1.220, on `SubagentStop` the harness delivers that field to the subagent that just stopped — not to the orchestrator such text addresses — and resumes that agent's turn. Warn-not-block is unchanged (`exit 0`, `decision:"block"` nowhere), and the `stop_hook_active` early exit covers the new channel too, which is not obvious given that the flag and its cap are built around *blocking* continuations: measured the same day, the Stop event ending a turn that `additionalContext` continued carries the flag `true`, so the hook speaks at most once per chain and needs no dedup state of its own.

- **`/audit-quality` told a preloaded run to write a file it cannot write.** The rubric is preloaded into the `quality-auditor` agent, which `/implement` spawns *synchronously* and continues by `SendMessage` — no fork, no notification to lose, and no `Write` declared. The REQUIRED file output now carries an explicit exception for that case, where the final message **is** the deliverable, and the neighbouring "this cannot spawn `completeness-critic`" note names the real reason in both contexts: in a fork the spawn tool errors, and inside a subagent `Agent` is stripped outright.

- **An agent's `tools:` list under-states what it gets.** Measured 2026-08-21 on 2.1.220: the harness hands `Write` and `Edit` to subagents that declare neither — including one with no preloaded skill, so it is not a union with a skill's `allowed-tools`. A `tools:` line reading `Read, Grep, Glob, Bash` states *intent*; "read-only" is enforced by the body of the prompt saying so, never by the frontmatter. `rules/_generic/delegation.md` records it next to the opposite case, where a listed tool is silently stripped.

- **A typed slash command that silently does not expand.** The harness expands a slash command only when the message *starts* with it, so a prompt pack that puts a heading or a `>`-quoted hand-off above its fenced block turns `/implement` into ordinary text: the skill never loads, nothing errors, and the session runs a lookalike procedure while both sides believe the contract is running. Fixed in the parts that ship, not only in the docs — `rules/_generic/core.md` (always-on) now tells the agent that a `/skill` present in the message with no `<command-name>` block **did not load**: name the command and let the operator re-send it, never substitute an improvised equivalent; `skills/prepare/reference/parallel-wave-execution.md` moves the session heading **outside** the fenced brief so the generated `implementation-prompts.md` starts each block with its command; and `skills/prompt-master/assets/prompt-pack-template.md` gains a fifth how-to-run rule telling the operator to copy the fence alone. `guide/{en,ru}/evidence.md` documents it as the fourth failure mode — none of the three escape hatches reaches it, because all three answer *"the user never named the skill"* and this one is the opposite — with the authoring rule also in `CONTRIBUTING.md`. Measured once, on an epic whose pack carried a note above 22 of 32 blocks: the run lost its mandatory architecture-audit phase, and the audit later returned two blocking regressions in code that had passed every acceptance check the session wrote for itself.

- **Catalog drift.** `/audit-quality`, `/deploy`, the `idea-skeptic` agent, and `docs/audience-altitude.md` shipped in 0.1.0 but were missing from the README's "What's in it" table and Layout tree (they were listed in `/which-skill` and `_kit/KIT.md` all along). All four are now in `guide/{en,ru}/reference.md`, and the 0.1.0 entry below names them too.

- **The format hook deleted imports it was supposed to leave alone.** `hooks/format-file.sh` ran `ruff check --fix`, whose F401 autofix removes an import written *before* its first use — the code then ships a call with no import that only fails at runtime, behind whatever `except` is nearest. Now `--fix --unfixable F401`. Confirmed cause of a defect recorded 12 times on one project.

## [0.1.0] — 2026-08-04

First public release. Everything below is the initial contents rather than a diff.

### Added

- **The pipeline** — `/discover → /analyst → /prepare → /implement`, plus `/idea` as a plain-language front door and `/scaffold` for "add another one like the existing one".
- **49 skills** across the pipeline, orientation (`/onboard`), explore-first (`/spike`, `/prototype`, `/select-tech`), alignment and design (`/grill`, `/domain-model`, `/codebase-design`, `/api-design`), quality (`/code-review`, `/audit-quality`, `/refactor`, `/diagnose`, `/test`, `/tdd`, `/test-spec`, `/arch-health`, `/clean-mvp`, `/sweep`, `/perf`), architecture evolution (`/decompose`, `/revisit`, `/distill`), ship-and-learn (`/rollout`, `/deploy`, `/preflight`, `/incident`, `/retro`), security (`/threat-model`, `/audit-security`, `/deps`), a local backlog tracker (`/to-prd`, `/to-issues`, `/triage`, `/epic-status`, `/close-epic`), and meta skills (`/which-skill`, `/prompt-master`, `/writing-skills`).
- **16 subagents** — reviewers, the adversarial verification pair `finding-verifier` + `completeness-critic`, `plan-challenger` and `idea-skeptic`, analysis agents, writers, and `backlog-researcher`. All share one **Finding Contract**, also shipped as `schemas/finding.schema.json`.
- **14 generic rule files** in three load tiers: `core.md` alone is always-on (~950 tokens), code rules are `paths: "**/*"`-scoped, and authoring/planning rules are scoped to where they fire.
- **5 stack rule packs** — `python`, `react-ts`, `ruby`, `rails`, `postgres`.
- **8 hooks** — `guard-bash`, `guard-secrets`, `format-file`, `sessionstart`, `precompact`, `subagent-stop`, plus the opt-in, off-by-default `verify-stop` and `skill-hint`. Every hook but `guard-bash` follows the **warn-not-block** contract.
- **Lifecycle skills** — `/bootstrap` (detect stack, write `PROJECT.md`, install and reconcile rule packs, wire `CLAUDE.md` and `settings.json`), `/update-kit` (3-way merge against `.kit-manifest.json`, preserving local adaptations), `/teardown` (clean up or fully uninstall).
- **Code-publish control** — `git add`/`commit`/`merge`/`push` denied in `settings.json` and hard-blocked by `guard-bash.sh`; the agent suggests the command, you run it.
- **Docs** — `self-knowledge.md`, `decision-craft.md`, `agent-failure-modes.md`, `working-with-agents.md`, `prompt-patterns.md`, `audience-altitude.md`, `observability.md`, `agent-teams.md`.
- **English and Russian READMEs**, kept in structural parity.
- **MIT license**, and a stdlib-only structural validator (`tools/validate-kit.py`) wired into CI.

### Notes

- **The always-on tier is deliberately one file.** Three A/B rounds measured no quality gain from a larger always-on rule tier and a ~13% cost increase, so it was cut to `core.md` alone. The honest claim is *the same result for less money*, not *it works better* — the kit publishes the results that argue against it alongside the ones that don't ([guide/en/evidence.md](guide/en/evidence.md)).
- **Copy-in is the only install path.** The Claude Code plugin model carries no `rules/` component and mandatorily namespaces commands, so a plugin cannot deliver either the always-on rules or an unprefixed `/discover`. An installer plugin is the likely future addition and ships only after an end-to-end smoke test. See [Distribution model](guide/en/why.md#distribution-model).
